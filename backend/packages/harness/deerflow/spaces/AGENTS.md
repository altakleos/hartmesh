# Storage Spaces

Private `native_create_evidence.py` owns durable managed-create evidence.
The operator atomically publishes `.native-creates` as 1000:1000/0700 outside
`.probe` and reclaimable roots; never repair a published conflict or erase stages.
Retain exact pool/directory/stage FDs and validate the named published record after
fsync. Strict bounded 0600 single-link versioned records correlate immutable
attempt/daemon/name/owner/thread/slots, never permission. The mixed scanner validates
v1 creates and private v2 `native_teardown_evidence.py` records under one bound.
Create-only ACK pruning never removes teardown. Exact primary correlation is unique;
publication retries reprove durability, and failed terminal fsync retains the record
and FD in memory. Same-daemon mutations only; never infer a target from slot order.
Pending survives restart; unknown/malformed/staging evidence fails closed and is
never evicted. `ready`/`creation_ready` and `teardown_revision` are memory-only;
IO methods belong off-loop. Teardown publication/completion closes the bridge's
revision gate until both typed indexes match the complete mixed snapshot. Restore
never drops retained accounting to manufacture readiness.
The already-installed canonical cleanup path can restore accounting while its
owner closes, retaining current owner/daemon proof and closed creation readiness.
This permission grants no resource effect or new runtime installation.
PoolRuntimeOwner retains the exact published namespace even through failed first
load and constructs the helper against that inode. Qualification installs the
AIO bridge and restored memory accounting before reconciliation/publication.
The bridge records before every managed native submission and inspects exact actual
daemon/ID/name/labels/slots before ACK. It retains verified identity before ACK or
worker return, quarantines unknown returned results and counts identity-less pending.
Partial publication restores accounting or disables admission. Keep this exact
helper through retry/drain; close after workers, provider and SQL disposal.
Do not activate reclamation using an empty inventory alone.

Private `runtime_owner.py` qualifies one participating native runtime per managed
pool before baseline provider lookup/construction. The operator creates its
stable empty 1000:1000/0600 file outside `.probe`; the Gateway never repairs or
replaces it. Retain the exact provider/host binding and inode through qualification
retry. Lifecycle-owned Docker runners inherit a duplicate FD; close only, never
`LOCK_UN`. Mark closing before producers/drains, then close after all workers,
provider shutdown and SQL disposal. `accepts`/publication checks are memory-only
under metadata locks; fresh physical proof runs off-loop before native effects.
Constructor reconciliation stays inert until binding. Unknown post-create
outcomes retain exact container identity in quarantine; never free capacity from
lost proof. A newly prepared NoUser chat may run mountless without qualification,
using provider-specific names and only its own fresh mountless client incarnation;
it cannot adopt, replace or remove foreign/native/unknown containers. This lock
does not qualify container absence or replace strict inventory/holder fencing.
Gateway transient ownership failures retry; generic unsupported hosts do not.

Ordinary chat routing uses private `chat_paths.py`, `chat_bridge.py` and
`chat_snapshots.py` adapters. `ChatStoragePaths` carries trusted role/root facts
and exact mount projections, never a cached grant. The Gateway owns async
qualification, closes SQL before filesystem verification and rechecks current
identity/roles/grants/bindings afterwards. No qualified User means no data/ACP
mount or legacy data-directory fallback. Company unavailability omits Shared
alone. Policy views and acquisition locks are operational state outside Spaces.
Host effects refresh admission and use pinned confined descriptors; ordinary
chat containers need no attachment row or per-chat probe. Do not infer permission
from a path projection, container name or cached client. Unsupported storage
credentials remain denied by the facade even when their active human identity
can run a text chat.

`provision.py` owns operator preparation and whole-plan byte/inode arithmetic.
The legacy script imports its unchanged entry point. Typed schema-2 inventories
carry user/assistant/employee/company kinds; schema-1 slots remain untyped.
Preparation never runs in a request. The Compose CLI validates confined paths,
holds one pool lock and publishes each completed slot atomically. Retained plus
missing slots must stay within `MAX_SPACES`; lowering counts never erases slots.
Typed mounted parents are root:1000 0770; unmounted mount points remain 0750.
Gateway group access permits host root renewal; sandbox binds never include the
parent. `storage_init` retains qualified image/root descriptors through repairs.
Startup `mount-all` repairs only parent permissions after allocation, three-way
UUID and writable loop-mount proof; it never recreates data/control. Full layout
repair remains in preparation and explicit repair. This corrects the design's
mounted root:root 0755 prerequisite; ordinary older file views remain admissible.

Typed `provisioning` keeps inventory order, skips unavailable/nonempty slots and
creates `LAYOUT` only after binding uniqueness flushes. Drain layout workers
before releasing allocation SQL ownership; `assign` drains the entire role-link
transaction. Bound/unclaimed sets retain uncertainty. Same-UUID growth requires
unchanged data/control inodes and nondecreasing bounds, recorded under resource
parent locks from the startup-pinned inventory. Prove bound volumes before taking
the short SQL publication lock, so stalled startup verification never retains
SQLite's application writer. Startup ownership and availability
are documented in [the guide](../../../../../docs/STORAGE_SPACES.md).

Private per-slot identity claims fence every bound/unclaimed/verified cache
publication. Snapshot claims before awaited metadata or filesystem proof, compare
by object identity, and retain free tombstones to prevent ABA. Allocation owns
an allocating claim from binding flush through caller commit or rollback; readers
cannot clear or promote it. Refresh publishes only after confirmed SQL commit.
These caches never replace current resource, grant, root or marker admission.

`host_release.py` owns actorless reclamation of already-deleted native resources,
only with the latest delete event's exact JSON false retention flag and fenced
attachments. Domain eligibility/containment is supplied by trusted callers,
never imported. Lock-only `host_locked(..., _before_lock=...)` prerequisites borrow
the transaction after SQLite writer reservation and before sorted Space locks.
Fresh admission and final domain publication callbacks borrow that same session;
external provider reservations must outlive workers and commit. No extra checkout,
commit, provider work or allocation lock belongs in the prerequisite hook.
Trusted callers may set `retain_unverified=True` to refuse effect-free forgetting
before operation discard, binding deletion or domain publication. The generic
default remains unchanged. `before_publication()` runs outside SQL after the
filesystem-complete checkpoint, including retries, before final writer/parent
admission. A failed hook preserves checkpoint and binding. Domain eligibility and
native provider semantics stay in the caller.

Immutable intent and versioned progress use the existing operation table with
private nonhuman writer label `host:space-release`; never resolve it as a principal
or grant it authority. This corrects CONTRACT 8.6's no-operation-row retry plan.
Only dedicated release interprets these records; ordinary settlement excludes
them. `release_filesystem.py` pins qualified descriptors, refuses an unwritable
parent before intent, and keeps its named private journal tied to the owned inode.
Bootstrap holds the resource parent until filesystem ownership exists, can purge
full data/control after intent, and preserves the marker/existing workflow lock.
Exchanges keep public roots present; exact opened root FDs govern purge. Commit
filesystem completion while retaining the binding before removing the journal.
Final rollback resumes that checkpoint even after partial journal unlink. All
path effects precede binding/domain publication commit; postcommit caches use CAS.
Capacity's read-only prefix check excludes unresolved sibling journals. Domain
scheduling arrives after provider containment qualification.

`binding_verified` projects facts after closing its SQL session; it grants no
admission. Assignable-slot snapshots exclude bound/unclaimed/unverified slots,
independently of account-seat occupancy. `user_spaces` gates `create` only;
the Gateway also refuses generic grant changes when it is false. User/Company
application links refuse destructive generic lifecycle/recovery POSTs, using
metadata-only current ADMIN/generation admission before the central refusal.
GET recovery and unowned generic lifecycle stay available. Host assignment
remains ungated. Availability uses one shared allowance formula.
Host-only provisioning admission runs before slot selection/layout, borrowing the
allocation transaction. It never bypasses custody or principal validation. The
Gateway serializes role assignment with seat release; business rules stay in app.

`incarnations.py` layers an immutable backing-handle expectation over physical
catalog facts. Bound consumers prove the private `.space-binding` marker through
pinned control descriptors before file/attachment use; raw refresh must retain
the expectation. The marker grants no authority. Allocation publishes it after
binding uniqueness flush and retains uncertainty on rollback. Startup-only
`incarnation_backfill.py` can add an absent marker to any existing verified binding
(including archived/deleted/mediated), under exact parent/binding/root ownership.
It preserves data/receipts, never overwrites conflict or adopts unbound roots.
Runtime admission/readiness never repairs absence. Gateway owns and drains the
one startup task after initial mount verification, separately from recurring
metadata verification.
Allocation owns SQLite's writer or a schema-scoped PostgreSQL transaction advisory
lock before current principal validation and slot selection, through caller commit
or rollback. Acquire allocation ownership before application admission locks;
never acquire it while retaining those locks in a release. Feature first-use links
recheck within that transaction before marker effects; existing links return only
after rollback and fresh grant admission. Losing requests leave unused slots empty.

`spaces/` owns generic resource identity and mandatory access, independent of
chats, agent definitions and feature installation. `storage/` remains the
separate content-addressed blob store. Product workflows do not belong here.

The registry is **host-only**. Bind its actor from authenticated host context
or a trusted nonhuman adapter; never deserialize an actor from a browser request
or impersonate an owner through `user_id`. `current_human_principal()` refuses
missing context, and `HostPrincipalResolver` rechecks active identities. Human
and nonhuman keys include their kind. A directory lookup validates existence;
it does not authenticate whoever supplied an ID.

Persisted facts live in `persistence/spaces/`: stable UUID resource/backing
handles, personal/company custody, mode, optional opaque controller binding,
generation, explicit grants and typed authority events. A company resource has
no creator/member foreign key and receives no ambient company-readable grant.
Personal custody may be provisioned only for the acting principal. Company
provisioning requires a trusted host capability, independent of admin labels.

READ, EXPORT, WRITE, OPERATE and ADMIN are explicit. Native WRITE requires READ
because a normal writable filesystem view can read existing bytes. Granting
new READ/EXPORT requires acknowledgement of existing data. ADMIN changes
resource facts; it does not grant native writes. Mediated resources require a
binding and never accept WRITE. A binding is opaque data, not evidence that a
controller is installed, compatible or authorized to mutate files.

`facade.py` binds the neutral extension API to current host actors. Its methods
take stable IDs/relative paths and never accept a caller-selected actor. Captured
handles cannot cross account context; every operation rechecks active identities
and current grants. Mediated primitives use OPERATE plus the installed controller
binding/settings in both intent and publication admissions. Provider capabilities
are explicit; absent storage/identity never returns an empty successful result.
Host credential admission is inherited by asynchronous work. PATs have no resource
scope: middleware denies facade actor projection and the Gateway omits their run
provider. Setting a typed actor cannot override a denied credential context.

Every metadata mutation reserves SQLite's writer before reading or locks the
Postgres parent row before grants. Revalidate actor/positive grant target inside
that boundary, validate persisted facts before using authority, compare the
expected generation, and commit the new generation with its event atomically.
Retired members remain revocable; retired administrators cannot satisfy the
last-active-administrator guard. No optional authorization setting bypasses
these checks. Unknown or malformed persisted facts fail closed.
Host-only grant admission callbacks add domain preconditions under the same
resource lock; they never bypass mandatory grants or reach browser/plugin input.
Consumers acquire their own SQL parent after the resource parent. A callback
rejection rolls back the grant, event and generation together.

`SpaceFiles` binds a qualified empty inventory slot atomically to resource
creation. Slot/UUID uniqueness prevents duplicate allocation; used bindings
are never recycled. Root inodes persist across Gateway restarts. `admitted()`
locks all scoped parents in sorted order and rechecks authority before I/O.
File intents commit before filesystem work; uncertain file/feature-workflow
outcomes block WRITE/OPERATE/ADMIN, while other pending actions block all access.
Busy refusals carry workflow/lifecycle cause. Completed IDs bind exact actor,
generation and request. Drain the entire owned mutation before cancellation.
Only exact ADMIN may catch `_volume`'s `BackingUnavailable`, skipping that
resource's workflow probe and pending-operation gate. Principal/grant/generation
and attachment guards remain mandatory; combined file rights and workflow lock
contention still refuse. Recovery retains its own volume proof before filesystem
mutation; accepting state may quiesce before refusing. Publish growth bounds only
after `verify_bound` succeeds, so the narrow
metadata fallback cannot commit unverified inventory geometry.
Cross-space copy needs source READ/EXPORT, destination WRITE, and source ADMIN

Host edits and multiple native attachments share ordinary filesystem semantics.
Invalid attachment phases always refuse; pending/fence_pending refuse ADMIN only.
Lifecycle effects and accepted state explicitly require every attachment fenced
under the final parent lock, including adapter loss. The host-only
attachment service reserves durable intents, commits exact container identity
before activation, and fences by confirmed removal on one qualified Linux Docker
host. Missing/foreign identity, unknown containment and adapter loss stay pending;
leases never prove retirement. Local endpoint checks retain root socket/alias
identity; a UID-1000 nonce-file probe proves pool and bound-view path coherence.
Private probe directories serialize cleanup through pinned descriptors; only the
controlled first runtime qualification clears the pool. Qualified adapter reuse
retains host/owner/evidence checks without another pool probe. Per-plan
`readonly_roots.py` projections bind qualified slots, backing/root revisions and
confined directories; the Gateway supplies role policy. They are configured RO
roots, never ordinary mount edges or grants. Company remains unreclaimable.
Resident preparation and reuse check exact mounts/network; joint
views require audience admission. No chat or task lifecycle owns it.

Native recovery quiesces all mounts, records backup identity before I/O and
validates archived trees before publication. Restore keeps root identity/current
grants and advances generation. Retain displaced bytes until SQL completion;
separately recorded cleanup failures consume quota. Archive is readable; delete
keeps tombstones/bindings/retention data. Owner-accepted uncertain state is failed,
not replayed or claimed complete. Mediated recovery requires its controller.

`filesystem.py` uses Linux openat2 BENEATH/NO_MAGICLINKS/NO_XDEV and owned

edit window; this primitive grants no writer exclusion. `backings.py` verifies
operator-prepared fixed ext4 images/mounts and platform reserve, rejects directory
fallback, and compares opened root incarnations. Native disk-limit qualification

Gateway actors come from authenticated request identity or an actually
attributed trusted internal owner. PAT storage scopes remain unsupported;

Generic mediated writes fail. HTTP ranges/MIME use owned confined descriptors
opened under current admission. Release SQL before streaming the owned inode;
slow clients must not reserve SQLite's global application writer. Open only
once and drain reads before close. Active content downloads; reads never cache.
